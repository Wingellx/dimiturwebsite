# £50 Booking Deposits Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A booking only becomes confirmed once the client pays a £50 deposit through Stripe Checkout (card / Apple Pay / Google Pay), with automatic refunds and self-serve moves 72h+ out, and Dim-only changes inside 72h.

**Architecture:** The booking insert stays the slot lock, but rows start as `pending_payment` with a 30-minute hold. Stripe's hosted Checkout takes the money; a signed webhook is the only thing that confirms a booking. All policy rules (72h cutoff, hold expiry, late-payment outcome) live in one pure module so they are unit-tested and shared by client and admin actions.

**Tech Stack:** Next.js 16.3 App Router (server actions + one route handler), Supabase (Postgres, service role), `stripe` Node SDK, Resend, Vitest (new, unit tests for pure logic only).

**Spec:** `docs/superpowers/specs/2026-10-27-deposits-design.md`

## Global Constraints

- Next.js 16 differs from training data: read the relevant guide in `node_modules/next/dist/docs/` before writing a route handler or changing server actions (AGENTS.md).
- Deposit: 5000 pence, GBP, flat. Never a different amount.
- Cutoff: exactly 72 hours before `starts_at` (`now <= starts_at − 72h` allows client cancel/move). Not calendar days.
- Payment hold: 30 minutes (Stripe Checkout minimum `expires_at`).
- Card data never touches this server — Stripe hosted Checkout only. Do not set `payment_method_types` (leaving it unset is what enables Apple Pay / Google Pay).
- Only the webhook confirms a booking. The success redirect never writes.
- Schema changes go in `supabase/migrations/003_deposits.sql` only; 001/002 are already applied to Dim's project `dsivhbmzpdjeqenzhglg`.
- Stripe test mode only (`sk_test_…`) in this plan. Secrets live in `.env.local` (gitignored); never print them.
- Balance is not taken, tracked or displayed. Copy says "£50 deposit, taken off your final price."
- Every refund call uses an idempotency key `refund-<booking id>` so retries never double-refund.
- Follow existing patterns: `"use server"` actions in `src/app/actions/`, `adminClient()` for writes, best-effort emails via `src/lib/email.ts` that never throw.

## Review Focus

1. **Client pays then closes the tab before the redirect** → webhook still confirms and emails; reopening the link shows "You're booked in". (Task 4 manual check.)
2. **Stripe delivers the same webhook twice** → second delivery is a no-op: no second email, no refund. (Task 2 test `paidOutcome` on `confirmed`; Task 4 manual `stripe events resend`.)
3. **Client A abandons payment on a slot, client B wants it** → slot looks taken for 30 min, then B can book it without anyone running a job. (Task 1 test `holdIsStale`; Task 3 insert releases stale holds.)
4. **Page loaded at 72h01m out, Cancel pressed at 71h59m** → server re-checks and refuses; page explains. (Task 1 boundary tests; Task 5 action re-checks server-side.)
5. **Move to a slot someone else grabbed while the client typed their reason** → friendly "just taken" error, booking and move history unchanged. (Task 5 manual check against 23505.)
